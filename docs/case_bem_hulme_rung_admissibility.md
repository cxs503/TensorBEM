# 锚点 BEM-HULME-HEMISPHERE：阶梯档的"自证健康"准入（E0）与 4096 档隔离

**锚点**：`CASE-BEM-HULME-HEMISPHERE`（算例池·Hulme 浮半球辐射/绕射，容差 <5%）
**本单**：m21334（自找活·tp-ds-4）

## ① 欠账

上一轮（dev report m20910 / m20515）把本仓延拓阶梯的 4096 面元档判为"规模断裂"，随后归因为
**节点环境（numpy 2.0.1 的线性驱动器）解错方程**：残差 4.9e-1、却报告满秩与健康条件数，
同一矩阵在健康控制面残差 1.8e-4。归因成立，但**证据链仍是手工的**——阶梯工件里没有任何一档
记录自己是用什么残差产出的，所以：

* 一个由失效驱动器产出的档，在工件里与健康档**长得一模一样**（只有数值不同，而数值差异正
  是判据要看的东西）；
* `analyse()` 把 4 档全喂进三参数收敛模型，于是 E2/E3/E4/E5/E6/E7/E8/E9 一起 FAIL，
  但 FAIL 的原因被记成"求解器不收敛"，而不是"其中一档是算术噪声"。

## ② 本单做了什么

1. **单格产出物带上求解健康**：`hulme_hemisphere_case._panel_cell` 现记录
   `radiation_relative_residual`、`diffraction_relative_residual` 与该格求解阶段守卫发出的
   `solve_warnings`（逐字保留）。数值逐位不变（64 档 A33/B33 与既有工件相同：0.358459837459815 /
   0.123144254091491）。
2. **准入判据 E0**（`tensorbem.benchmarks.hemisphere_independent_convergence`）：档只有在
   *记录了自己产出时的残差* 且 *残差 < 1e-2* 时才进入拟合；残差超阈的档被**剔除**并列入
   `dropped`，没有残差记录的档（早于守卫的工件）**准入但标记为 unproven**，不得被当成健康。
3. **工件换代**：`inhouse_ladder_ka2_healthy.json`（64/256/1024 三档，逐档带残差）成为拟合输入；
   首轮 `inhouse_ladder_ka2.json` 保留为诚实记录，不再进入拟合，其 4096 档的失效原因写进
   `admissibility.superseded_reason`。

## ④ 注意点

* **E0 不能证明残差之外的东西**：一档残差健康、数值仍可能因别的缺陷错，E0 只封住
  「驱动器没解方程却照样入账」这条已知通道。
* **门槛不是精细量**：健康控制面 1024 档 1.8e-4、失效节点 4.9e-1，两条数量级之间任何阈值都行，
  1e-2 取的是"同量级即拒收"的保守侧（与 m20910 建议一致）。
* **第四档仍缺**：健康环境的 4096 档已递交集群（作业 cj3341，n315，numpy 2.4.6，rc=0），
  但本单会话内未取回其载荷，故提交的阶梯止于 1024 面元，`absence_reason` 已写进工件。
  E7/E9 因此保持 FAIL——**不因"看起来快收敛了"而放行**。

## ⑤ 误差判定（是否 <3%）

- 1024 面元（算例判据所用）：最坏 B33 相对参考 **1.15%** → **<3% ✅**
- 求解残差 3.24e-04 → 远低于 1e-2 门槛 → 该档**自证健康** ✅
- 4096 档（首轮）**54.2%** → **>3% ❌**，已由 E0 隔离，不再污染裁定
