## 1. Case, geometry and parameters

The gap this closes is registered in `docs/ice_mass_loading_verification.md`:

> the `ice_rao` module requires `k_i H >= 3`; finite-depth ice Green function is
> not implemented.

That guard excludes the entire Arctic shelf.  The physics is the mass-loading
ice cover (Weitz & Keller 1950) over water of depth `H`:

| quantity | value |
|---|---|
| frequency `omega` | 1.0 rad/s |
| ice thickness `h_i` | 0.9 m (ladder B varies 0.2-2.5 m) |
| ice / water density | 917 / 1025 kg/m^3 (`tensorbem.ice` defaults) |
| mass-loading parameter `mu = rho_i h_i / rho_w` | 0.805171 m |
| cut-off `sqrt(g/mu)` | 3.4899 rad/s |
| body | closed icosphere r = 1 m, centre at z = -1.5 m (strictly submerged) |
| water depth `H` | 10, 15, 20, 30, 50, 100 m |
| panels | 20 (one frequency re-run at 80) |

## 2. Method

Mass loading enters only through the Robin condition on `z = 0`,
`dphi/dz = K(omega) phi` with `K = omega^2/(g - mu omega^2)`.  That is the same
condition the open-water finite-depth kernel implements with `nu = omega^2/g`, so
the ice-covered finite-depth Green function is the finite-depth kernel evaluated
at `nu = K`.  Two kernel identities are therefore checkable exactly, and both are
gated in `tests/test_ice_finite_depth.py`:

* `G(nu=K)` satisfies `dG/dz = K G` on `z = 0` (relative residual < 1e-10) and
  `dG/dz = 0` on `z = -H`;
* the propagating root solves `k_i tanh(k_i H) = K`, residual 9.576e-16 1/m.

The finite-depth solver infers `omega = sqrt(g nu)` from `nu`, which is wrong
under ice, so the damping is rescaled by `omega/sqrt(g K)` (added mass is the
real part of the same impedance and is untouched); `result.implied_omega` makes
the factor visible and a test pins the identity.

Independent route used as the reference where it is defined: the deep-water ice
solver `tensorbem.ice_rao` (Kelvin kernel, no bottom), which refuses `k_iH < 3`.

## 6. Caveats found while doing this

1. **Mesh is the dominant error, and it is measured, not assumed.** Refining the
   sphere from 20 to 80 panels changes heave added mass by +30% and heave damping
   by +85% (generated `mesh_check` block).  The ladder is therefore a
   *route-consistency* study: both routes see the same panels, so their agreement
   says the two kernels and the frequency bookkeeping are consistent; it does not
   establish converged absolute coefficients.  No mesh-convergence study at 320+
   panels was run (cost: the finite-depth assembly is roughly `N^2 x modes` and a
   320-panel solve exceeds the mission budget).
2. **Mode truncation is not the cause of that drift.** At H = 20 m the 20-panel
   answer is unchanged to 5e-5 between the automatic mode count (872) and 2000
   modes, so the 20->80 panel change is geometry/quadrature, not the evanescent
   series.
3. **The deep-water comparison is truncation-limited, not physics-limited, above
   `k_iH ~ 20`.** At H = 200 m the automatic mode count saturates and the
   agreement degrades to 5e-3; the useful band for cross-validation is
   `3 <= k_iH <= 11`, which is where the ladder sits.
4. **Discrete reciprocity holds to 1.7e-8 relative, not to round-off** (6.2e-5
   absolute on a 3.7e3 scale).  The symmetry gate is set at 1e-6 relative.
5. **Off-diagonal damping may be negative** (sway-pitch is), so only the diagonal
   is constrained to be non-negative.
6. Diffraction under ice in finite depth is **not** provided: the finite-depth
   solver ships no incident-wave machinery.
