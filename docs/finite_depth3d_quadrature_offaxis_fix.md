# 有限水深三维自由面 Green 函数「离轴缺陷」的根因与修复（m13811）

**仓库** TensorBEM · **分支** `agent/m13811` · **EDIT_WHITELIST**: `src/tensorbem/`, `tests/`, `docs/`, `scripts/`, `outputs/`
**类型**：缺陷修复（对已合并功能做验证复核时暴露的真 bug）+ 失效测试补齐（把"缺陷存在"的钉扎改成"缺陷已闭合"的钉扎）

## 1. 案例介绍（问题是什么）

TensorBEM 的三维有限水深自由面 Green 函数有两套独立实现：

* `tensorbem.finite_depth3d.green_function_3d` —— John (1950) 特征函数级数（eigenseries）；
* `tensorbem.finite_depth3d_quadrature.green_function_finite_depth_3d` —— 波数积分（kernel subtraction + 极点主值）形式。

第二套实现自 m2930 起背负一条"离轴（R>0）不收敛"的记录：与深水 Kelvin 核相比相对误差
0.34 / 0.56 / 3.2 且**与水深无关**（m6304 把它归因为"波数积分振荡尾 `J_0(kR)` 的处理"），
模块顶部因此挂着 `STATUS: UNVERIFIED -- do not use in a solver`，并有两条 strict-xfail 测试把它钉住。

本单从"验证欠账"入手复核这条欠账，结果发现：**欠账的归因是错的，它不是积分精度问题，
而是一个把坐标钳位的输入 bug。**

## 2. 怎么做的（方法与工具链）

1. 复现记录的数字：`nu = 0.6`，源点 `(0,0,-1.0)`，离轴场点 `(0.5,0,-0.5)`、`(2.0,1.0,-1.5)`，
   水深 ladder 4…128 m；参考解为 `tensorbem.free_surface3d.green_function_3d`（深水 Kelvin 核，
   独立实现）与 eigenseries（另一独立表示）。复现值与 m6304 表一致（0.345 / 3.20）。
2. 二分定位：把 `_wave_integral`（纯波数积分）与 scipy `quad` + `scipy.special.j0` 的同式
   高精度积分对比 —— **两者一致到 1e-12**；把 `_q_values`（被积函数）与 scipy 同式对比 ——
   **一致到 1e-14**。即积分与被积函数都没问题。
3. 用 spy 包住 `_wave_integral` 打印实参：`radius = array([0.])` —— 明明给了离轴目标，半径却是 0。
4. 定位到 `_green` 里的两行：

   ```python
   tgt = np.minimum(tgt.copy(), 0.0)   # 整个点阵被钳位
   src = np.minimum(src.copy(), 0.0)   # -> x = y = 0，所有配对都退化成"轴上" R = 0
   ```

   原意只是把刚好落在自由面上的 z 分量夹到 0（深水模块 `free_surface3d.py:382` 写的就是
   `tgt_clean[..., 2] = np.minimum(...)`，是本模块写漏了下标）。后果：**任何离轴场点都被
   静默投影到源轴上**，`R` 恒为 0。
5. 修复：只对垂直分量钳位（两行改四行 + 注释），其余不动。
6. 证据：`scripts/m13811_finite_depth3d_quadrature_offaxis_fix.py` 程序化生成
   `outputs/m13811/fix_verification.json`（本页所有数字的来源）、
   `outputs/m13811/table.md`、图 `docs/figures/fig_m13811_fd3d_offaxis_fix.png`。
   "修复前"一列是**对旧代码的精确复现**（旧代码等价于把目标投影到轴上，故用投影目标调用现
   内核即得旧值，例如 h=8、`(0.5,0,-0.5)` 旧值 `0.1495+0.1219j`，与修复前实测一致）。

## 5. 注意点（坑 / 局限 / 适用范围）

* **坑（本次真因）**：`np.minimum(array, 0.0)` 这类"整体钳位"在只有一维需要夹紧时是静默
  错误，且症状（离轴偏大、与 h 无关）看起来极像"积分尾处理不当"，导致两轮审计（m2930、m6304）
  都在积分器里找原因。教训：**先核对被积函数的实参，再怀疑积分格式**；不同 R 的点若给出
  完全相同的 R=0 结果，就是输入被投影的指纹。
* 旧的 strict-xfail 机制这次按设计工作：修复后 `test_quadrature_offaxis_defect_is_documented`
  立刻红（"defect unexpectedly resolved"），强制更新钉扎而不是悄悄变绿。
* 级数（eigenseries）在 `R = 0` 轴上仍发散（`K_0(mu_n R)` 的对数奇性），这是表示本身的局限，
  本次未动；轴上参考一律用深水核（h ≥ 64 时 1.8e-7）。
* 本次只复核了值核 `order=0` 与由同一 `_q_values` 生成的 `dG/dz`（`order=1`）；水平导数、
  doublet 核、三维有限水深绕射/辐射求解器仍不在本模块范围内（roadmap 未变）。
* 没有做的：把该核接到面元装配上（自面元/近奇异积分仍是 `docs/finite_depth3d_gradients.md`
  §110 记的欠账）。本单只把"核本身不可信"这条去掉。

## 6. 误差判定（是否 <3%？）

| 关键量 | 基准 | 修复前 | 修复后 | <3% ? |
|---|---|---|---|---|
| 离轴值核 h=4…128，4 点 | eigenseries（独立表示） | —（未测，输入被投影） | ≤ 1.94e-10 | **是**（远优于 3%，达舍入） |
| 离轴值核 h ≥ 20（`nu*h ≥ 12`） | 深水 Kelvin 核 | 0.34 / 3.20 | ≤ 1.41e-04 | **是** |
| 离轴值核 h=4（`nu*h = 2.4`） | 深水 Kelvin 核 | 0.34 | ≤ 6.0e-2 | **否**，且**不应**是：`nu*h = 2.4` 只略高于 `k0*h ≈ pi/2` 的"浅水-深水"过渡，深水核本身不是该点的真值；此项只作趋势判据（随 h 单调下降）。真正的"对错"由与 eigenseries 的 1e-10 一致给出 |
| 轴上点 h ≥ 20 | 深水 Kelvin 核 | 1.9e-6（本就正确） | 6.4e-5…1.9e-7 | **是** |

结论：**修复后离轴值核在 h ≥ 20 的全部算例与深水基准误差 ≤ 1.41e-4（<3%），与独立
eigenseries 表示一致到 1.94e-10；模块的 `UNVERIFIED` 状态可以撤销。**
