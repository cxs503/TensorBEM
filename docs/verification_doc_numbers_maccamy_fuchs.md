## 1. 为什么要做这件事

`docs/marine_bem_benchmarks.md` §4.9 的表 8（波浪力/力矩收敛阶梯、等效惯性力系数 \(C_M(ka)\) 频率扫掠）与
表 9（内域共振波数处未增广 BIE 与 Schenck CHIEF 的对比）是 TensorBEM 对「不规则频率」这一穿水浮体面板法
最著名陷阱的唯一量化证据，文档据此断言：

* 力误差二阶收敛（观测阶 2.040 → 2.007），\(N=128\) 时 \(1.32\times10^{-4}\)；
* 条件数随加密单调下降（3.015 → 2.434）；
* \(J_1\) 偶极共振令未增广解的 \(\cos\theta\) 分力失真 **10.35%**，5 个内部 CHIEF 零场点把它压回 **0.28%**，
  同时把条件数从 665 降到 3.34。

**这条链上没有任何测试**。`grep` 全仓：`7.72e-3`、`1.9e-4` 等 Ursell 声明数字已被 m2136 的
`declared_numbers` 注册表覆盖，但 MacCamy–Fuchs 表 8/表 9 的 28 个数字既不在注册表里、也没有 pytest 断言。
 Helmholtz 装配（`helmholtz.py`）、Hankel/Bessel 层（`analytic.py`）或 CHIEF 增广逻辑任何一处改动，都可以让
文档整体失效而 CI 全绿——这正是 m2136 在 Ursell 上已经踩过的坑（文档表落后代码一个修订，审计判 HONEST FAIL）。
本单把它补成可执行判据。

## 2. 方法

1. **零手抄登记**：把表 8/表 9 的 28 个数字逐条抄进 `verify_doc_numbers.py::DECLARED`，每条带
   `(表, 量, 面元数或 ka, 声明值, 相对容差)`；容差按有效位数定：解析基准量 0.5%，四位有效数字的条件数 0.5%，
   观测阶 1%。
2. **重算**：`verify_doc_numbers.run_benchmark()` 以子进程运行发布代码的
   `python -m tensorbem.benchmarks.maccamy_fuchs --panels 16 32 64 128`（8 s，单线程），不调用任何内部函数，
   保证验的是用户可复现的那条路径。
3. **观测阶自算**：不照抄文档的 2.040/2.016/2.007，而是在代码里用相邻两级 `h_max` 与误差比现算
   \(\log(e_{c}/e_{f})/\log(h_c/h_f)\)，再与声明值比——否则「收敛阶」这条断言等于自证。
4. **物理断言**（`test_chief_suppresses_the_dipole_resonance`）：不止对数字，还对文档主张的**模态选择性**下断言：
   两个共振都令未增广条件数 > 100；轴对称模态对 \(\cos\theta\) 力正交（误差 < 1%）而偶极模态失真 > 5%；
   CHIEF 后两者条件数 < 10、力误差 < 0.5%。
5. **跨进程可复现**：同一 CLI 跑两次，逐字段比对，排除随机/线程数导致的抖动。

## 5. 注意点（踩的坑 / 局限 / 适用范围）

1. **不要用 `run()` 直接验文档**：基准的 CLI 路径（`--panels 16 32 64 128`）才是文档给出的复现命令，
   内部函数签名可以改，CLI 输出格式是文档契约。判据钉在 CLI 的 JSON 上。
2. **四位有效数字的声明必须配宽容差**：文档写 `2.31`，实测 `2.3135`，若按 1e-4 判会误报 DRIFT；
   容差应按声明的有效位数定，不能一律 1e-6。这是本单唯一「设计判断」而非计算的地方。
3. **观测阶必须现算**：若把 2.040 抄成常量再断言，等于没验收敛性；本实现从测量误差现算相邻级阶数。
4. **模态选择性是更容易失效的部分**：数字可以微调，但「轴对称共振不污染 \(\cos\theta\) 分力」这一物理主张一旦被破坏，
   表 9 的整段叙事就错。故单列一条物理断言（含 `> 100` 条件数、`< 1%` 与 `> 5%` 的分野），而不只比数字。
5. **局限**：本轮只覆盖二维 Helmholtz 分离变量算例（\(ka{=}1.0\)、\(h/a{=}3.0\)、\(N\le128\)）；
   三维 Kelvin 核（§4.10 Hulme 半球）、Wang/Linton 潜没球、椭球 1280 面元等声明数字仍未进注册表
   （前两者三维稠密装配，重算成本高；椭球 1280 面元按 m2136 测量需 >25 min，本机 load15 ≈ 114 按容量纪律未跑）。
6. **未做的事**：没有改动任何求解器代码（无 bug 可改——28 条全 PASS）；没有触碰 `declared_numbers.py`
   （在 agent/m2136 未合并分支上，避免并行注册表造成合并冲突），本单的护栏是独立的、可单独合并的。

## 6. 给下次自找活的线索

  合并时应把本单的 `DECLARED` 表作为条目源喂进统一注册表，删掉重复的 runner。

  贯底柱 CHIEF 表（本单已覆盖）→ Hulme 半球 3-D → 椭球 1280 面元（heavy）。

  选 CI 级判据时要按这条成本谱分配。
