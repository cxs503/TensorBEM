# FMMOperator 电荷向量缓存失效缺陷修复（m16000）

> 能力：`tensorbem.fmm.FMMOperator` 作为**线性算子**的语义
> 修复文件：`src/tensorbem/fmm.py` · 测试：`tests/test_fmm_operator_linearity.py`
> 证据（全部数字由 `scripts/fmm_linearity_bench.py` 程序化生成，本文件表格由脚本注入）：`docs/fmm_operator_linearity/evidence.json`

## ① 案例介绍

`FMMOperator` 为 Laplace 单层核 `G(r)=1/(4πr)` 提供多极展开加速的 matvec
`φ = S q`。多极系数 `M_{l,m}` 是电荷向量的**线性泛函**：

```
M_(l,m)(αq1 + βq2) = α M_(l,m)(q1) + β M_(l,m)(q2)
```

但实现把多极系数缓存在 `_multipole_matrix` 里：`setup(points, charges)` 提供电荷时构建，
否则**首次** `matvec` 用当时的电荷构建，之后永不失效。于是同一算子在**第二次**用不同电荷
调用时：近场（每次按当前 `charges` 直接求和）用的是新电荷，远场（`_far_contributions` 读缓存）
用的是旧电荷——算子不再是线性的。触发场景=多个右端项（多 RHS 分块）、迭代求解器
（GMRES/GMRES(m) 每次迭代都换电荷向量）、以及任何复用算子的批处理。

## ② 怎么做的

1. **先证缺陷（红）**：新写 `tests/test_fmm_operator_linearity.py`，在**未修改**的 `fmm.py` 上运行，
   首条即失败：`second call error 2.464e+00 (first 1.048e-08)`。
2. **修复（最小改动）**：给缓存加**电荷指纹**。`FMMOperator` 新增 `_cache_points/_cache_charges`
   两个字段，记录缓存对应的源点与电荷（`copy=True`，故调用方原地改数组也能被发现）；
   新增谓词 `_multipole_cache_valid(sources, charges)`；`matvec` 改为「指纹不匹配即重建多极系数」；
   `setup()` 同步刷新/清空指纹（重新 `setup` 不带电荷时清掉旧多极）；顺带把 `charges` 长度
   不等从 `IndexError` 变成显式 `ValueError`。
3. **A/B 对照**：`scripts/fmm_linearity_bench.py` 用 `_PrefixCacheOperator`（唯一差异=缓存谓词恒真，
   即修复前语义）与修复后算子在同一几何（200 源点聚簇 + 3 个远场靶点，`max_leaf=25`）上对跑，
   p=1..8；另做 GMRES 端到端与缓存开销测量。
4. **回归**：`tests/test_fmm.py`（23 例）+ `test_fmm_cost_audit.py` + 新文件，共 49 例全绿。

## ③ 计算结果

第二次调用（换了电荷向量）相对直接求和的最大相对误差：

| p | first call (both) | fixed, 2nd call | pre-m16000, 2nd call |
|---|---|---|---|
| 1 | 4.489e-04 | 2.204e-04 | 2.465e+00 |
| 2 | 1.086e-04 | 4.449e-04 | 2.464e+00 |
| 3 | 3.726e-06 | 3.698e-05 | 2.464e+00 |
| 4 | 1.333e-06 | 2.897e-07 | 2.464e+00 |
| 5 | 6.323e-08 | 3.859e-08 | 2.464e+00 |
| 6 | 1.048e-08 | 1.239e-08 | 2.464e+00 |
| 7 | 7.270e-10 | 2.085e-09 | 2.464e+00 |
| 8 | 1.833e-11 | 2.936e-10 | 2.464e+00 |

- 修复前：误差**在 p=1..8 上恒为 2.46**（≈246%），完全不随展开阶改善——说明误差不是截断误差，
  而是缓存造成的**系统性错位**（新电荷近场 + 旧电荷远场）。
- 修复后：p=6 时 1.24e-08，p=8 时 2.94e-10，随 p 下降（与首次调用同量级）。
- 首次调用修复前后**逐位相同**（`fixed_first_err == prefix_first_err`，8/8 行），证明修复没有
  改变正常路径的数值。

GMRES 端到端（icosphere(1)，N=80，p=10，`max_leaf=16`，rtol=1e-12）：

| 项 | pre-m16000 语义 | 修复后 |
|---|---|---|
| 迭代数 | 2 | 2 |
| GMRES 报告残差 | 3.267e-16 | 3.267e-16 |
| 真残差 ‖Sq−b‖/‖b‖ | 3.751e-16 | 3.751e-16 |
| 解 vs 稠密解相对误差 | 6.717e-16 | 6.717e-16 |

缓存指纹的开销（N=200，同一电荷重复调用 vs 换电荷触发重建，20 次取最优）：
命中 4.24 ms / 重建 4.00 ms（比值 0.94）。
即「每次调用多一次指纹比较」的代价在测量噪声内——多极系数构建 O(N(p+1)²) 远小于近场 O(N·N_leaf)。

## ⑤ 注意点 / 局限

1. **GMRES 实验对本缺陷不敏感**：N=80 的 icosphere 面元间距相对远场判据太近，几乎全部
   (target, leaf) 对走近场直和，因此两条残差曲线完全重合、解误差都是 6.7e-16。该实验验证的是
   「修复后算子可安全放进迭代求解器」这条语义（回归价值），**不构成**对该缺陷的判别性证据；
   判别性证据是 ③ 的 p 扫描 A/B。真正能放大的几何（两个远分离面元簇、小 `max_leaf`）未做，
   如实登记为未覆盖项。
2. **`far_fraction()` 诊断量自相矛盾（疑似独立缺陷，本单未修）**：在同一几何上
   `far_fraction(targets)` 返回 0.0（暗示无远场对），
   但修复前第二次调用的 2.46 误差只能来自远场缓存路径——两者不能同时成立。本单范围是缓存语义，
   不动该诊断函数；已在下方「建议后续」登记。
3. 修复是**语义修复**而非精度提升：首次调用逐位不变，精度上限仍由 p 与近/远场判据决定（无 M2L，
   单层多极 → 严格说是树码而非教科书 FMM，见 `docs/fmm_acceleration/report.md` §5）。
4. 指纹比较用 `np.array_equal`（O(N)），对 N=20k 每调用约几十 µs 量级，成本可忽略；
   若将来进入热循环可换哈希，但当前不需要。

## ⑥ 误差判定（关键量 vs 基准）

| 关键量 | 基准 | 修复前 | 修复后 | 是否 <3% |
|---|---|---|---|---|
| 第二次调用 matvec（p=6） | 稠密直接求和 | 2.464e+00（246%） | 1.239e-08 | 修复后 ✅，修复前 ❌ |
| 第二次调用 matvec（p=4） | 稠密直接求和 | 2.464e+00 | 2.897e-07 | 修复后 ✅ |
| 叠加性 S(q1+q2)−(Sq1+Sq2) | 0 | 1.428e-01（14%） | <1e-6（测试断言） | 修复后 ✅ |
| 首次调用 matvec | 稠密直接求和 | 1.048e-08 | 1.048e-08（逐位不变） | ✅ |

**结论：修复后关键量误差 1.2e-08 ≪ 3%，修复前 246% 属不可接受；本单为缺陷修复，非对标精度研究。**

## 建议后续（供下次自找活）

- 判别性 GMRES 实验：两个远分离面元簇（各 icosphere(0)）+ 小 `max_leaf`，把残差曲线分离开。
- `far_fraction()` 的矛盾（⑤-2）单独立项核对 `_near_mask`/`far_fraction` 的配对定义。
- FMM 入 BEM 真正求解路径（`solve_laplace_surface*`）的端到端加速比与精度包线，仍未做。
