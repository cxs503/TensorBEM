**状态**：✅ 结案 —— 审计 2026-10-24 记的 honest FAIL（128 面元附加质量误差实测 8.51e-3 vs 文档 7.7e-3，偏差 10.6%）已定位根因，文档与钉扎测试同步更新。

## 1. 欠账的来源

`expand_audit_tensorbem.md` §2.2 复算 README 与 `docs/marine_bem_benchmarks.md` §4.6 声明的 Ursell 潜没圆柱辐射精度时，用与文档完全相同的命令：

```
python -m tensorbem.benchmarks.ursell_cylinder --panels 128
```

得到附加质量相对误差 `8.513031e-03`，而文档写 `7.72e-3`，**误差本身的相对偏差 10.6%**。当时无法归因，只能记为 honest FAIL 并建议「复现文档生成环境或更新数字」。该欠账自 2026-10-24 起未处理。

## 2. 三方复算：代码错了还是文档旧了

把文档写作时的代码快照**只读**导出（`git archive 878834a`，不改工作树、不动 `.git`），在同一机器同一 numpy 上跑同一命令，与当前分支对照：

| 量 | 快照 878834a（文档写作时） | 当前分支 HEAD | Ursell 解析参考 |
|---|---|---|---|
| 附加质量 A | `2564.813781` | `2566.834334` | `2545.167248` |
| A 相对误差 | `7.719152e-03` | `8.513031e-03` | — |
| 阻尼 B | `2753.508146` | `2754.470100` | `2718.153952` |
| B 相对误差 | `1.300669e-02` | `1.336059e-02` | — |
| 近场/远场阻尼比 | `1.005701` | `1.005341` | 1 |

**判决**：快照跑出 `7.719152e-03` / `1.300669e-02` / 比值 `1.0057`，与文档表格的 7.72e-3 / 1.30e-2 / 1.0057 **逐位吻合**。参考侧（解析多极子解）两版完全相同，说明 **analytic 参考没变、变的是面元解**。所以不是 README 抄错，而是**代码在文档成文之后改过、文档没跟**。

## 3. 根因：求解器重构改变了势的求积

`git log -S "smooth_nodes = min(panel_nodes, 6)"` 唯一定位到提交 **`267d5a3`**（"Add marine rigid-body Neumann, diffraction, Helmholtz, and 3-D Kelvin BEM suites"，2026-10-23）。该提交同时改了 `docs/marine_bem_benchmarks.md`（新增 §4.7–4.9），但**没有重新生成 §4.6 的 Ursell 表**。

改动实质：物面势积分从「所有面板统一用 `panel_nodes` 点 Gauss」改为「Rankine 对数项用解析原函数 + 光滑自由液面余项用 `min(panel_nodes, 6)` 点 Gauss」。新写法在自面板不再触碰 `log(0)`，原则上更稳；代价是光滑项求积阶被钉在 6，`panel_nodes` 因此**在 6 以上完全不起作用**（§5 实测）。

对结果的影响：128 面元附加质量 +0.079%、阻尼 +0.035%。**该位移比格式本身的离散误差（0.85%）小一个量级**，所以既不是回归，也不能声称哪一版"更准"——它落在离散误差之内。

## 5. 顺带查清：`panel_nodes` 在 6 以上是惰性的

| 24 | $8.51\times10^{-3}$ | $1.34\times10^{-2}$ |

三者**逐位相同**（差异 < 1e-15），证实 §3 的机制判断。已写成测试 `test_smooth_part_quadrature_saturates_above_six_nodes`：以后若有人改掉这个截断，测试会失败并迫使其同步文档，而不是让读者误以为"调大 `panel_nodes` 能变准"。

## 7. 局限（如实写）

1. **没有判定新旧求积哪个"更准"**：两者都以一阶趋近同一解析极限，0.079% 的位移小于 0.85% 的离散误差；本报告只证明"位移存在且来自 267d5a3"，不主张优劣。
2. **没有跑到 1024 面元以上**：256 面元误差 4.3e-3；再加密受本机负载约束（load15 ≈ 105，nproc=128）未做，收敛阶已由 64/128/256 三点确定。
3. **未改求解器代码**：本单是验证/文档欠账收口，不动数值实现；若日后要提升该算例精度，应走向 MFS 或高阶面元，而非调 `panel_nodes`。
