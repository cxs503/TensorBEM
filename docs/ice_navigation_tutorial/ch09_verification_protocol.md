## 1. 为什么教程也需要验证协议

技术教程最常见的失效模式不是"讲错公式"，而是：

* **数字来源不可追**：某个百分比从一篇报告手抄过来，报告版本变了教程没变；
* **能力被夸大**：把文献里的公式写成本仓算出的结果；
* **判据没有出处**：写"一般要求误差小于 5%"却说不出是谁的要求；
* **章节不自足**：必须读完全部章节才能跑出一章的数，实际上不可讲授。

本教程用四道机器门禁把这些失效模式挡住，而不是靠作者自觉。

## 2. 方法与关键设置

### 2.1 证据分级（五档）

| 等级 | 定义 | 可接受的使用方式 |
|---|---|---|
| REAL | 真实算法 + 可复算参考（解析解/已合并证据/程序化渲染） | 可作为结论 |
| MOCK | 硬编码/随机占位 | 只能出现在被显式标注的占位处，禁止作为结论 |
| STUB | 空壳接口 | 必须标注"未实现"，禁止作为结论 |
| WITHHELD | 证据不足或能力不在本仓 | 只能作为"欠账"出现，必须写出归属 |
| NOT_SUPPORTED | 明确不支持 | 必须写出替代路径 |

本教程的 4 个计算章全部 REAL；ch06–ch08 以 WITHHELD 记账；没有任何一章把 MOCK/STUB
当真结论使用。

### 2.2 容差层级

| 场景 | 容差 | 依据 |
|---|---|---|
| 对解析解 | < 3%（或更严，如 ch02 的 1%） | 精确参考无实验不确定度可吸收误差 |
| 算例池 | < 5% | 案例池容差（ch04 的 Lamb 极限） |
| 冰区工程复算 | ≤ 10% | 平台 KPI（静水 ≤5% / 冰区 ≤10%） |
| 任意场景 | > 15% 不可接受 | 平台精度红线，不得以措辞放行 |

### 2.3 四道门禁（`tests/test_ice_tutorial.py`）

1. **判据重算门**：`criteria.py` 里所有 `computable=True` 的行在 pytest 里重新计算并
   必须通过。判据不是文档里的装饰，而是可执行断言；
2. **渲染指纹门**：章节内嵌数值块必须与"现在重算 + 重渲染"的结果**逐字一致**。
   任何人手改一个数字，门就红；
3. **出处完备门**：每个 `Criterion` 的 `ref_key` 必须命中 `REFS`（构造期抛异常），
   且每章的判据表 ≥3 行；没有出处的判据无法进入教程；
4. **章节自足门**：每章必须含学习目标、前置知识、判据表、注意点与局限、参考文献、
   复现命令，且图文件存在。缺一段就红。

### 2.4 新增一章的正确流程

1. 在 `examples/ice_tutorial/criteria.py` 注册判据（每行带 `ref_key` 与证据等级）；
2. 若该章有现场计算，在 `examples/ice_tutorial/model.py` 增加 `chapterNN()` 并返回
   `metrics`（判据消费的键）；
3. 写 `docs/ice_navigation_tutorial/chNN_*.md`，留好
   `<!-- AUTO-NUMBERS:chNN -->` / `<!-- AUTO-CRITERIA:chNN -->` 标记对；
4. 在 `render.py` 的 `CHAPTER_FILES`（必要的话还有 `FIGURE_FUNCTIONS`）登记；
5. `python examples/ice_tutorial/render.py` 渲染，`pytest tests/test_ice_tutorial.py -q` 变绿。

## 4. 结果与图

本章无图。理由：本章的"结果"是门禁的通过/失败状态，可视化成图片不会增加信息量，
反而会诱导读者把绿色图当成"物理正确"的证据。门禁状态请直接看：

```bash
python -m pytest tests/test_ice_tutorial.py -q            # 四道门
python examples/ice_tutorial/render.py --check            # 判据 + 指纹
```

## 5. 注意点与局限（证据分级）

1. **REAL**：四道门禁都在 CI 可跑；判据重算与指纹比对是硬断言。
2. **门禁覆盖的是"一致性"，不是"物理正确性"**：判据全绿只说明代码、文档、数字三者
   一致且解析锚满足；它**不能**证明模型适用于某片真实海域。
3. **指纹的脆弱性**：格式或字段一改，指纹就变——这是设计意图（要求同步重渲染），
   但也意味着跨平台浮点差异可能造成假红，故指纹只覆盖少数关键标量的**渲染字符串**。
4. **WITHHELD 不是失败**：它是诚实记账。把 WITHHELD 改成 REAL 才是失败。
5. **honest-FAIL 纪律**：门禁不通过时，报告里必须写"未通过 + 原因 + 影响面"，
   不得用"工程可接受"替代。
