## ⑤ 注意点

- **前科的代价**：机械 overlay 在这条链上曾静默丢内容。本次两处注册表冲突若"取
  theirs"会丢掉 main 的 34 行表 10–12 数据；若"取 ours"则整个 PR 白做。语义并集是
  唯一不丢东西的解，并用步骤 4 的审计把它变成机器可验。
- **空文件陷阱**：审计脚本第一版用 `bool(lines)` 判"文件是否在合并树里"，把 0 字节的
  `docs/m3566/outputs/m3566/rigid_body.err` 误判为丢失；改用 `git cat-file -e` 后 PASS。
- **`sys.path` 遮蔽陷阱**：本机 `site-packages` 有 7 个历史工作树的 `.pth` 入口
  （首个是 `m3967/src`），不显式 `PYTHONPATH=<本工作树>/src` 时 `import tensorbem`
  会解析到别人的源码树，测试结果不可信。本单所有运行均显式指定 `PYTHONPATH` 并用
  `tensorbem.__file__` 回读确认。
- **机器负载**：合并与复算期间宿主 load average 883–1736（128 核被整个舰队占满），
  单条三维自由液面求解被拉长 1–2 个数量级。因此本单跑的是**核心**测试（注册表结构
  守卫 23 个 + fast/standard 两层端到端复算），**没有**跑 92 个文件的全量套件。
  这是如实声明的覆盖缺口，不等于"CI 全绿"。
- **边界**：本次只做合并治愈，不改任何数值算法；`rigid_body` 行的定义、容差与文档
  引用完全沿用分支原样（未为凑 PASS 调参）。
