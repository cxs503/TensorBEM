## 1. 案例介绍（问题背景与对象）

对象不是求解器，而是**智能体的信息供给面**。开工时的可核事实：

| 项 | 数值 | 出处 |
|---|---|---|
| 本仓可抽取的事实单元 | 24 311 条（`docs/*.md` + `dev_report_*.md`） | `cli extract` |
| 其中 TOLERANCE / NEGATIVE / TRAP / VERDICT / PIN / CONTEXT | 1697 / 938 / 95 / 1471 / 857 / 19253 | 同上 |
| 决策相关行占比 | **21%**（≈ 79% 是无决策含量的叙述） | 同上 |
| 同类任务历史报告 | 60 份 `dev_report_*.md` | 仓内 |

物理/工程背景一句话：**上下文预算就是新的内存墙**。把仓库塞进窗口，79% 的预算买的是背景叙述；
凭记忆写，则丢掉"上次这条路已经被证伪""阈值是 3% 不是 15%"这类真正决定成败的行。

参数表（协议的可调项）：

| 参数 | 默认值 | 含义 |
|---|---|---|
| `budget_tokens` | 400–1200（按任务型） | 硬上限，超出跳过不截断 |
| `local_share` | 0.70 | 两流配比：工作包自身工件 vs 跨文档 KO |
| dedupe 阈值 | 3-gram Jaccard 0.85 | 近重复抑制 |
| L1/L2/L3 预算 | 1400 / 900 / 2200 token | 三层记忆容量 |
| 半衰期 | ∞ / 12 / 30 单 | 留存分衰减 |
| 压缩节奏 | 每 5 单 或 层用量 ≥85% | 谁先到算谁 |

## 2. 怎么做的（方法 / 流程 / 工具链）

1. **抽取**（`extract.py`）：markdown 逐行成原子事实单元；跳代码块；列表符/表格竖线清洗；
   每单元绑 `source` + `lineno` + 该行 `sha256`。kind 用策展语义正则（阈值词+数字 / 负面词 / 坑词 /
   裁定词 / pin 词），**零领域词表**。
2. **打分**（`pack.py`）：自带 BM25（CJK 二元组 + ASCII 词）与倒排索引——24k 语料一次建索引 1.0 s，
   单查询全库打分 0.1 s 级。
3. **组装**：floor（每 floor kind 保 1 条）→ 贪心（`BM25 × kind 权重 × profile`）→ 硬预算 → 回填。
4. **两流配比**（`pack_two_stream`）：`local_sources` 拿 70% 预算，跨文档拿 30%，floor 全局只买一次。
5. **零手抄闸门**（`cli verify`）：回读源文件、复算每行 sha256，任一不符 `exit 1`。
6. **三层记忆**（`memory.py`）：留存分衰减 + 保留底线 + 双条件遗忘 + 归档 + append-only 遗忘日志 +
   `verify_forget_log` 复算。
7. **A/B**（`ab.py`）：留出式构造（查询段=标题+§1/§2，目标段=§5 注意点/§6 误差判定），
   4 臂 × 4 预算 × 40 任务。
8. **图**（`make_figures.py`）：读 A/B JSON 出图，数字程序化注入，无手抄。

## 5. 注意点（坑、局限、适用范围）

1. **第一轮我们打输了，且这轮没删掉**：只有全局检索打包器时，800 token 下召回 0.141 < 读自己文档 0.257。
   根因是语料对称性（目标本来就写在工作包自己的文档里），不是打分器不行。对策是两流配比；但第一轮
   结果完整留在 `ab_results.json`（`brief_global` 臂仍在网格里，从未移除）。
2. **大预算下优势收缩**：1600 token 时 head_dump 召回 0.897 > 0.815。CI 相接，不算显著，但足以否掉
   "干货包永远更好"。协议的卖点在紧预算（400–1200）而非大预算。
3. **复用密集型负载会溢出不丢**：仿真终态 L2 2400 > 900、L3 4457 > 2200。双条件遗忘（`use_count==0`
   且足够旧）在"什么都刚用过"的负载下不放行任何遗忘。这是有意取舍（宁溢出不丢验收线），
   但下一版需要层内硬上限 + 降级到归档索引。
4. **token 是估计不是计费**：CJK 1.5 字/token、其余 4 字符/token；未用真分词器校准，
   统一偏高或偏低会整体平移预算口径，不改变臂间比较。
5. **零手抄闸门只保证"行没被改动"**，不保证"这行说的是对的"——源头造假它抓不到。
6. **离线 ≠ 在线**：本 A/B 测"该进窗口的进了没有"，不测"任务质量提升"。在线 ≥40 单对照未做（需派单）。

## 6. 误差判定（关键量 vs 基准，逐项回答是否 <3%）

本单是信息策展基础设施，**没有物理基准量**，故按"基准=对照臂"的方式逐项给差：

| 关键量 | 度量 | 对照（基准） | 本协议 | 差 | 是否 <3% |
|---|---|---|---|---|---|
| 留出事实召回 @800 | 40 任务均值 | head_dump 0.257 | 0.513 | +99.6% | 不适用（不是误差，是提升） |
| 验收判据召回 @800 | 同上 | head_dump 0.206 | 0.544 | +164% | 不适用 |
| 闸门命中 @800 | 同上 | head_dump 0.250 | 0.800 | +220% | 不适用 |
| 留出事实召回 @1600 | 同上 | head_dump 0.897 | 0.815 | −9.1% | 否（**本协议在此时落后**） |
| 预算合规 | 包 token ≤ 预算 | — | 4/4 预算全合规 | 0 | **是（0%）** |
| 逐字可复算 | verify 命中率 | — | 32/32 = 100% | 0 | **是（0%）** |
| 确定性 | 同输入两跑 sha256 | — | 完全一致 | 0 | **是（0%）** |
| 遗忘链完整 | `verify_forget_log` | — | ok 189 / bad 0 | 0 | **是（0%）** |

显式回答"是否 <3%"：**凡有数值基准（预算合规、哈希复算、确定性、遗忘链）误差 = 0，<3% 成立；
凡属"效果对照"的量（召回/闸门）不存在 3% 判据，只报差值与 CI，并明确 @1600 召回落后 9.1%**。
