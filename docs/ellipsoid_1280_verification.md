# Ellipsoid 1280-panel verification: direct reproduction of the documented row

**Scope**: closes the open item left by the 2026-10-24 expansion audit
(`expand_audit_tensorbem.md` §2.3, mission m238): the 1280-panel
(subdivisions=3) translating-ellipsoid row quoted in `README.md` (Milestone 3)
and `docs/classical_benchmarks.md` §3 had **never been directly reproduced** —
the audit ran only 320 and 5120 panels and extrapolated. The registry in
`tensorbem/benchmarks/declared_numbers.py` already carried the three declared
values at tier `heavy`, but no test ever executed that tier for the ellipsoid.

**Verdict**: the documented row is reproduced to all four quoted significant
figures on all three axes, and the documented observed orders (2.01/2.00/1.99)
are recovered from the freshly re-run 320→1280 pair. The heavy tier is now an
executable claim (`tests/test_declared_numbers.py`, gated by
`TENSORBEM_HEAVY_TESTS=1`).

---

## 1. Case

Translating triaxial ellipsoid in an unbounded inviscid incompressible fluid,
no free surface. Semi-axes `(1.5, 1.0, 0.75)` m, density 1025 kg/m³, unit
translation speed along each principal axis in turn.

| quantity | value |
|---|---|
| semi-axes | (1.5, 1.0, 0.75) m |
| volume | 4.71239 m³ (mesh ratio 0.991394 at 1280 panels) |
| Lamb shape factors | 0.400928 / 0.670713 / 0.928360 (sum 2.0 to 1e-15) |
| exact added mass | ρVαᵢ/(2−αᵢ) = 1211.052 / 2437.154 / 4184.389 kg |
| mesh | flat-faceted icosphere, 642 vertices, 1280 panels, h_max 0.24697 |
| equation | exterior Dirichlet, constant panels, `solve_laplace_surface` |
| reference | Lamb closed-form (independent of the BEM code) |

## 2. Method

1. `python -m tensorbem.benchmarks.ellipsoid_added_mass --subdivisions 3`
   (1280 panels) and `--subdivisions 2` (320 panels), both with
   `PYTHONPATH=<worktree>/src`; raw outputs committed verbatim in
   `outputs/ellipsoid_1280/subdivisions_{2,3}.json`.
2. Machine judgment: `python -m tensorbem.benchmarks.declared_numbers
   --tiers heavy --strict` re-runs the heavy tier (ellipsoid 1280 + Ursell 256)
   and exits non-zero on any drift beyond the 1.5e-2 relative tolerance;
   report in `outputs/ellipsoid_1280/declared_numbers_heavy.json`.
3. Regression lock: `test_heavy_tier_reproduces_the_documented_ellipsoid_numbers`
   (HEAVY) asserts the three ellipsoid keys PASS.
4. Figure `outputs/ellipsoid_1280/ellipsoid_1280_verification.png` is
   regenerated by `outputs/ellipsoid_1280/make_figure.py` from the raw JSONs;
   nothing is transcribed by hand.

No quantity exceeds the 3 % threshold; the honest accuracy statement is

still near first order (1.29–1.66e-2) from polyhedral-edge singularities".

## 5. Pitfalls and scope

* **Editable installs lie about which code runs.** The system `tensorbem`
  resolves to *another agent's worktree* (m57, 30+ PRs behind). A first
  1280-panel run launched without `PYTHONPATH` silently used that stale tree;
  the ellipsoid code paths happened to be byte-identical there, but the
  relaunch with the explicit `PYTHONPATH` is the official one. Always check
  `tensorbem.__file__` before trusting a benchmark run.
* **`pkill -f <pattern>` kills your own shell** when the pattern occurs in the
  command line; kill by PID file instead.
* **Scope**: only the 1280-panel row of the classical ellipsoid table was
  re-verified; the 20/80 rows were not re-run (the 320 row was, and matches).
  The 5120-panel point in the figure is the audit's recorded value, not a
  fresh run (machine load was above the heavy-compute threshold).
* Compute footprint: 1280-panel three-axis solve ≈ 11 min single-process
  (≈7 cores via BLAS); 320-panel ≈ 20 s.
