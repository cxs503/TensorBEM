## 1. 案例介绍（为什么选这件事）

### 1.1 选题依据：缺口账里唯一还开着的「验证欠账」

`expand_audit_tensorbem.md` §4.2 记了两条未结项，其中一条是：

> **椭球基准 1280 面元未直接复现**：实测 5120 面元误差 ~1.1e-3，声明 1280 面元 ~4.5e-3；
> 按 O(h²) 收敛，320→1280 误差应降 16 倍：x: 1.63e-2/16 ≈ 1.02e-3（但声明 4.17e-3）。

这条欠账的性质是**覆盖缺失**，不是数值漂移：README 与 `docs/marine_bem_benchmarks.md`
把「椭球 1280 面元三轴相对误差 4.17e-3 / 4.46e-3 / 4.94e-3、观测阶 1.99–2.01」当作经典层
的招牌数字印在正文里，而 `docs/benchmark_pins.json` 此前只钉 6 个**二维**用例
（3 个圆柱 + 3 个 Ursell），三维经典层与二维椭圆柱**一个数字都没有测试读**。
`doc_pins.PinCase` 的 `metrics` 字段甚至已经写好了「`axes.0.added_mass_relative_error`
这样的点路径用于椭球三轴行」的注释——能力在场、用例缺席。

审计本身还留下一个**方法论错误**需要纠正：320→1280 面元不是「网格加密一倍」。icosphere
细分级别 +1 使面元数 ×4、`h` 减半，二阶方法误差因此降 **4 倍**而非 16 倍；按 4 倍算，
1.6313e-2 / 4 = 4.08e-3 与声明 4.1679e-3 吻合（实测比值 3.9140，观测阶 2.007）。
也就是说声明数字自洽，欠的是**守护**，不是**精度**。

### 1.2 物理背景与几何（被守护的量）

* **三维椭球**（半轴 1.5 / 1.0 / 0.75，ρ=1025）：平移附加质量 `m_A,i = ρVα_i/(2−α_i)`，
  `α_i` 为 Lamb 形状因子（代码每次求值校验 `Σα=2`）。边界迹取精确线性解
  `u = −U k x_i`、`k = α_i/(2−α_i)`，流体侧法向导数精确为 `q_e = −U n_i`，因此这是
  **离散化 + 外域积分方程**的精度判据，不含级数求值误差。
* **二维椭圆柱**（a=1.5, b=0.75）：`m'_{A,x} = ρπb²`、`m'_{A,y} = ρπa²`，用真正的二维外域
  算子 `S q_e = (½I − H)u`（圆截面的「线性势内外同一调和延拓」巧合在椭圆上不存在）。

## 2. 怎么做的（方法/流程/关键设置）

1. **先跑证据、后改代码**：独立进程单线程重算 320 面元（11 s）与 1280 面元（~60–90 s），
   与声明逐位对照——1280 面元实测 4.167936e-3 / 4.462121e-3 / 4.935932e-3，
   与声明 4.1679e-3 / 4.4621e-3 / 4.9359e-3 **逐位一致**，欠账确认是「无人守护」。
2. **把声明变成可执行判据**：在 `src/tensorbem/benchmarks/doc_pins.py` 中新增 4 个用例
   （`ellipse_added_mass_2d_128_{x,y}`、`ellipsoid_added_mass_320`、`ellipsoid_added_mass_1280`），
   复用既有点路径机制取三轴行；1280 面元标记 `slow=True`（~90 s），不进默认 CI。
   `python -m tensorbem.benchmarks.doc_pins --write --include-slow` 重写 pin 文件：
   `git diff` 显示 6 条既有用例数值**零变化**（仅 `commit` 字段更新），新增 4 条。
3. **补上 pin 文件管不到的方向**：新增 `tests/test_classical_layer_claims.py`，把数字从
   **散文里解析回来**（README 经典层段落 + 报告表 3/表 4），与 pin 值按「印刷位数的半个末位」
   容差比对；观测阶不出手动抄，而是用钉住的 320/1280 两行 `log(e_320/e_1280)/log(h_320/h_1280)`
   现算后与表格印刷值比。
4. **成本纪律**：本机 load15≈110–150（128 核），全程单线程、未起集群作业；最贵的 1280 面元
   只跑两次（一次独立复核、一次 `--write`），新增默认 CI 成本约 +13 s（320 面元 9.8 s +
   两个椭圆柱用例 1.6/1.7 s）。

## 5. 注意点（坑与局限）

- **审计里的「16 倍」是错的外推**：icosphere 细分 +1 = 面元 ×4、h 减半，h² 方法误差降 4 倍。
  按 16 倍去判会把正确声明判成错；本单把这一条写进测试注释（观测阶由 `h_max` 比值现算），
  防止后来者再按面元数直接比。
- **pin 只护代码，不护散文**：`--check` 证明代码仍产出 pin 里的数，但 README 可以写别的数。
  新增的 `test_classical_layer_claims.py` 就是补这一半：从散文里解析数字再和 pin 比，
  容差按印刷位数（三位有效数字 → 5e-3 相对），且有一条负控断言「声明是四舍五入过的、
  与实测不相等」，保证这条测试不是恒真。
- **慢用例必须显式标记**：1280 面元约 90 s，若混进默认 CI 会让每轮慢一倍；用 `slow=True`
  并断言其保持 slow，成本可控（默认 CI +13 s）。
- **未做**：椭圆柱观测阶 2.00 依赖 64 面元行，而 64 面元未入 pin（只钉 128），因此该阶未被
  测试守护；审计里的 5120 面元点仍未入 pin；`--write` 重写后 pin 文件的 `commit` 字段更新为本
  分支 HEAD，属正常再生成。
- **未触及求解器**：本单只加判据与证据，未改任何内核；因此对「求解器精度」不加分。

结论：缺口账 §4.2 的「椭球 1280 面元未直接复现」**结清**——声明数字逐位复现（最大相对偏差
8.2e-4），此前是**守护缺失**而非精度问题；4 个用例 + 8 条判据已使这些数字此后任何漂移都会变红。
同一份判据首次执行即全绿，无 honest FAIL。
