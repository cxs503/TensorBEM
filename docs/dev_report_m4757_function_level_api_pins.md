## 1. 案例介绍（为什么做这件事）

TensorBEM 已有一条成熟的**模块级**证据链：`tensorbem.capability_evidence` 要求每个包模块
至少被一个测试文件*提及*（imports / `tensorbem.<leaf>` 文本 / `python -m tensorbem...`），
失败即红。这条棘轮很有效，但它守的是**模块粒度**，而公开 API 的粒度是**函数**。

本单把扫描粒度下沉一层：对 `src/tensorbem/**/*.py` 做 AST 提取（模块级公开函数，非 `_` 开头），
再对 `tests/**/*.py` 做 AST 引用收集（`Name`/`Attribute`/`ImportFrom`），求差集。
结果（`outputs/m4757/untested_public_api.json`，完全程序化）：

| 口径 | 数量 |
|---|---|
| 包内模块数 / 公开函数总数 | 114 / 735 |
| 无测试引用的公开函数总数 | 133 |
| 其中 `benchmarks/` 脚本辅助函数 | 123 |
| 其中**主干数值模块**（`src/tensorbem/*.py`） | 20 → 本单钉住后 **10** |

主干这 20 个里有一批是**主路径数值算子**：三维湿表面网格生成（`floating_sphere_hull_mesh`）、
入射 Airy 波场、刚体广义法向、有限水深本征模与其范数、消逝根抛光、深水极限诊断、
Helmholtz 双层位矩阵、CHIEF 内点、条件数趋势。它们的共同点恰恰是**都有闭式对照**，
所以「没被测」不是「不可测」，是欠账。

**物理/几何背景**（本单覆盖的算例参数）：

| 量 | 设定 |
|---|---|
| 球冠浮体 | R = 1.0 / 2.0 m，球心 z₀ = −0.5 / −0.75 m，截平面 z = 0 |
| 入射 Airy 波 | ν = ω²/g = 0.7 m⁻¹，振幅 A = 1.7，浪向 β = 25° |
| 有限水深本征模 | ν = 1.2，h = 7.0 m，取 4 个消逝模 + 传播模 |
| 消逝根抛光 | ν = 0.8，h = 6.0 m，6 个根，Newton 3 步 |
| 深水极限诊断 | ν = 0.5，源点 (0,0,−1)，目标环 r = 1.5，h = 1…80 m |
| Helmholtz 双层位 | 半径 1 m 的 128 面元圆，σ ≡ 1，k = 0.2…2.0，内/外探针偏移 1e−2…5e−2 m |
| 条件数趋势 | icosphere 细分 1–2（80 / 320 面元），直接法 |

## 2. 怎么做的（方法与关键设置）

1. **扫描定位**（只读）：AST 求差集，输出机器可读清单；先把「哪些函数没跑过」变成数字，
   再挑有闭式对照的主干函数下手——不做「看见热点就补测」的随机补测。
2. **逐函数语录解析锚点**（锚点必须**独立于包内其它代码路径**，否则只是自洽回归）：
   - `floating_sphere_hull_mesh` ↔ 球冠闭式：浸没体积 `πH²(3R−H)/3`、湿表面积 `2πRH`、
     水线半径 `√(R²−z₀²)`（H = R − z₀，球心在水面**下**，湿表面是**大**冠）；
   - `incident_airy_wave_3d` ↔ 深水 Airy 运动学：`∂φ/∂z = νφ`（任意深度成立）、
     `|φ| = (gA/ω)e^{νz}`、以及浪向旋转等价性（把点旋转 −β 等价于把浪向转 +β）；
   - `rigid_body_normals_3d` ↔ 闭曲面恒等式：`∮n dS = 0`、`∮(x−c)×n dS = 0`、矩心平移的刚体变换关系；
   - `finite_depth.mode_norms` ↔ Sturm–Liouville：本征模满足 `u′(−h)=0` 与 Robin `u′(0)=νu(0)`，
     故 `∫u_m u_n = norm_n δ_mn`；闭式范数与 200 点 Gauss 积分逐模对表；
   - `finite_depth3d.vertical_mode` ↔ 定义 `cosh(k₀(z+h))` 及深水极限 `→ e^{k₀z}`（排除 z = −h 端点，
     该点 cosh(0)=1 而 cosh(k₀h)=e^{k₀h}/2，比值带因子 2，属边界例外而非误差）；
   - `polish_evanescent_roots` ↔ 色散残差 `|μtan(μh)+ν|/ν` 必须被压到机器精度且不跳支；
   - `deep_water_limit_error` ↔ 该诊断本身要**有分辨力**：深水端趋零、浅水端 O(1)（负控）；
   - `assemble_helmholtz_double_layer` ↔ 双层位跳变关系 `u_out − u_in = −σ`（奇异部分与 Laplace 核同）；
   - `default_chief_points` ↔ 正多边形内切圆内包含性（独立于模块自带的 point-in-polygon）；
   - `condition_number_trend` ↔ 与单层 `estimate_operator_conditions` 逐级一致。
3. **跑数**：`PYTHONPATH=src python3 tools/m4757_analytic_pins_artifacts.py`
   （一次性产出 JSON / 图 / 报告表，报告表格由脚本注入，不手抄）。
4. **测试固化**：`tests/test_core_api_analytic_pins.py`，12 条用例（含 3 条负控/守卫：
   z>0 与 ν≤0 必须抛错、浅水端必须 O(1)、`count=0`/非 mesh 必须报错），全绿 3.25 s。
5. **容量纪律**：入场 load15 ≈ 124（nproc=128）⇒ 只做轻量活：本单全部计算是 2-D 面板 ≤ 320、
   3-D 面板 ≤ 4 千、单次求解，无长时迭代；测试总耗时 3.25 s，图 130 dpi。

## 4. 结果分析

- **球冠几何**：体积/湿面积误差随细分级别约按 O(h²) 下降，细分 4–5 时进入 10⁻³ 量级；
  水线多边形内接于解析圆（无一点越界），弦高随细分单调减小（表 A 末列）。这条把
  `floating_sphere_hull_mesh` 从「无人验证」变成「有闭式解逐级比对的几何入口」——
  这正是 Cb/L/B 类几何量在水动力求解之前必须先过关的那一步。
- **有限水深本征模**：闭式范数与 200 点 Gauss 积分逐模一致到 2e−14，交叉内积 ≤ 6e−14，
  色散残差 ≤ 2e−8（二分）→ **3.9e−15**（Newton 3 步）。说明 `mode_norms` 的闭式不是「又一个公式」，
  而是该 SL 问题的正交归一常数，且 `polish_evanescent_roots` 确实把残差压到机器精度（表 B、C）。
- **深水极限**：h=20 → 1.9e−4，h=40 → 1.9e−5，h=80 → 2.2e−6，约每加倍衰减 10×；
  浅水端 h=1 时 0.79（O(1)）——诊断在两端都有分辨力，不是恒零的空壳（表 D、图中）。
- **Helmholtz 双层位**：k=0.2…2.0、内/外探针 2e−2…5e−2 m 下，`|\\|jump\\|−1|` 在 1e−2 偏移时最大
  5.5e−2，2e−2 及更远 ≤3%（表 E）；随偏移增大与面元加密而收敛，属近奇异 Gauss 求积的固有误差，
  不是跳变关系失效（虚部恒为实部的 <10%，方向正确）。
- **条件数趋势**：与逐级 `estimate_operator_conditions` 完全一致（表 G），确认它是薄封装而非第二套逻辑。

## 5. 注意点（踩过的坑 / 局限 / 适用范围）

1. **球冠高度符号**：球心在水面**下**（z₀<0）时，湿表面是**大**冠，H = R − z₀ 而非 R + z₀。
   我第一版写成 R + z₀，实测体积差 4.4 倍才发现——闭式锚点本身也必须先自检。
2. **水线不是解析圆**：切平面与三角网格相交给的是**弦**上的点，水线多边形内接于真圆，
   半径最大偏差随细分按 4× 收敛（表 A）。断言只能写「≤ 解析半径 + 0 且弦高单调下降」，
   不能写「等于解析半径」。
3. **Airy 波定义域 z ≤ 0**：z 方向无法做中心差分（水面之上函数按设计抛错），必须用
   单侧二阶格式，且单侧模板自下而上时符号是 (3, −4, +1)；写成 (−3, +4, −1) 会整列反号。
4. **`cosh` 归一化的端点例外**：`vertical_mode` 在 z = −h 处 φ = cosh(0) = 1，而 cosh(k₀h) ≈ e^{k₀h}/2，
   比值带因子 2。深水极限只能在离开 z=−h 处比较——不是代码 bug，断言的适用域要写清。
5. **近奇异求积**：双层位跳变在探针偏移 → 0 时误差上升（1e−2 偏移 5.5%）。测试用 2e−2 是
   精度与稳定性的折中；若要更好只能上近奇异求积（仓内已有 `near_singular` 模块，未在本单范围内）。
6. **未做**：`benchmarks/` 下 123 个脚本辅助函数仍未逐个覆盖（它们是报告生成器，
   判据是「报告与 pin 表一致」，已由 `doc_pins`/`declared_numbers` 那套棘轮守）；本轮没有新增
   函数级覆盖率门（只留可重跑的扫描 JSON），因为并发开发者多，新增硬门会伤及无关 PR——
   建议下一轮由 owner 决定是否把「主干公开函数必须有测试引用」升级成 CI 棘轮。
7. **本单未改任何 `src/tensorbem` 代码**：12 条用例全部一次通过（除上述我自己的断言错误），
   即被钉住的 10 个函数**未发现数值缺陷**——这是验证结清，不是修 bug。
