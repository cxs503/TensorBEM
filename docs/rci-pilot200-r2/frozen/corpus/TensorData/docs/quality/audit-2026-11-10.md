# Quality Engine Audit — 2026-11-10

Stage 1 pre-migration audit of quality-check capabilities, per the phased handover
plan (owner-directed; Claude Code executes in-repo migration). Evidence references
use `file:line` against commit `bba91a6`.

## 1. Where quality-check logic lives today

All executable quality logic is inline in one FastAPI route:
`run_quality_checks` at `tensordata/main.py:233-322` (89 lines). It mixes five
concerns in a single function:

1. artifact lookup + storage resolution + path confinement (`main.py:239-249`)
2. streaming SHA-256 / size re-measurement (`main.py:251-258`)
3. general integrity rules — 3 findings (`main.py:259-266`)
4. tabular CSV rules — 6 findings, wrapped in one `try` (`main.py:267-306`)
5. `QualityReport` persistence (`main.py:308-322`)

The engine depends on FastAPI (`HTTPException`), SQLAlchemy (`Session`), the ORM
model, and settings. It cannot run outside the API process, cannot be composed,
and cannot be versioned per rule.

## 2. Current rules, profiles, report structures

### 2.1 Rule inventory (hardcoded, no registry)

| rule_id | severity | fires when | evidence |
|---|---|---|---|
| `file.non_empty` | error | measured size == 0 | `main.py:259` |
| `file.size_matches_metadata` | error | measured size != metadata | `main.py:261` |
| `file.sha256_matches_metadata` | error | measured hash != metadata | `main.py:263` |
| `tabular.header_present` | error | no header or any blank header cell | `main.py:272` |
| `tabular.rows_present` | error | zero data rows | `main.py:289` |
| `tabular.row_width` | error (+count) | row width != header width | `main.py:291` |
| `tabular.missing_cells` | warning (+count) | blank cell after strip | `main.py:293` |
| `tabular.duplicate_rows` | warning (+count) | exact row seen before | `main.py:295` |
| `tabular.csv_parseable` | error | `UnicodeDecodeError`/`csv.Error` | `main.py:305` |

Findings are dicts `{rule_id, severity, message[, count]}`. Report status is
`failed` iff any finding has severity `error` (`main.py:308`).

### 2.2 Profiles

Two profiles, selected by `if payload.profile == "tabular":` (`main.py:267`).
`general` = the three `file.*` rules only. There is no profile abstraction, no
composition, and `QualityCheckCreate.profile` is `Literal["general", "tabular"]`
(`schemas.py:126`).

### 2.3 Report model and versions

`QualityReport` (`models.py:92-104`): `artifact_id`, `artifact_sha256`,
`profile`, `ruleset_version`, `status`, `summary_json`, `findings_json`,
`executed_by`, `created_at`. `ruleset_version` is the hardcoded string
`"0.1.0"` (`main.py:313`) — one global version, no per-rule version, no record
of which rules actually executed.

`summary_json` keys are contract surface: `general`/`tabular` both carry
`{size_bytes, sha256_verified}` (`main.py:266`); `tabular` adds
`{row_count, column_count, columns, missing_cells, duplicate_rows,
malformed_rows}` (`main.py:297-304`).

**Known semantic defect (D1):** `QualityReport.artifact_sha256` stores the
*metadata* hash, not the measured one. On a tampered payload the report field
and its own `file.sha256_matches_metadata` finding disagree. The measured hash
is currently recorded nowhere.

## 3. DatasetVersion quality gate — actual behavior

`create_dataset_version` (`main.py:401-449`):

1. duplicate version guard (409, `main.py:388-389`), member dedupe (422,
   `main.py:391-393`), unknown artifacts (422, `main.py:397-399`)
2. rights gate: asset `rights_status == "prohibited"` → 422 (`main.py:405-409`)
3. required profile derivation (`main.py:410-415`): `tabular` when
   `asset_type ∈ {table, timeseries}` or `media_type ∈ {text/csv,
   application/csv}`, else `general`
4. picks the **latest** report for (artifact, profile) by `created_at desc`
   (`main.py:416-423`) and requires `artifact_sha256 == artifact.sha256` **and**
   `status == "passed"` (`main.py:424-433`) — content-addressed re-check
   discipline: editing the payload invalidates prior reports
5. manifest members snapshot `quality_report_id`, `quality_profile`,
   `quality_ruleset_version`, `quality_status` (`main.py:434-449`); the manifest
   is canonical JSON and SHA-256 hashed (`main.py:461-462`)

The gate is sound for what it checks. Stage 1 does not change it.

## 4. Report ↔ manifest linkage

One-directional, via member snapshot fields listed above. The manifest does not
embed rule-level findings; it references the immutable report row. Dataset
versions therefore quote the ruleset version that produced the pass decision.
With D1 present, a tampered artifact cannot pass the gate (hash mismatch), but
reports produced against tampered content still mis-state their input hash in
`artifact_sha256`.

## 5. Test coverage and gaps

Existing (all real execution, no mocks of the check itself):
`tests/test_api.py` (closed-API 503; full lifecycle: upload dedupe, download
ETag, quality pass/fail on malformed CSV, gate blocked without report, manifest
snapshot fields incl. `quality_ruleset_version == "0.1.0"`, prohibited rights,
duplicate version 409, unknown artifact 422, provenance validation + lineage);
`tests/test_client.py` (SDK happy path + structured errors, MockTransport);
`tests/test_migrations.py` (0001 upgrade/downgrade round-trip).

Gaps (stage 1 must close):
- empty-file artifact (`file.non_empty`) — untested end-to-end
- tampered payload (`sha256_matches_metadata`, `size_matches_metadata`) —
  untested; nothing on disk is mutated in any test
- explicit assertions on `missing_cells` / `duplicate_rows` counts and findings
- the "general cannot substitute for tabular" comment at `test_api.py:152-159`
  creates a general report but never asserts substitution is rejected
- no rule-version or executed-rules recording to test
- no large-input streaming verification (memory-boundedness)
- `test_migrations.py:17-24` asserts only 0001 tables — `quality_reports`
  (0002) is never checked; downgrade coverage for 0002 absent

## 6. Migration compatibility risks

1. `test_api.py:173` pins manifest `quality_ruleset_version == "0.1.0"`, and
   `docs/api/quickstart.md:170` documents severity semantics (missing/duplicate
   = warnings; empty/malformed/width/integrity = failures). Both must hold after
   migration.
2. `summary_json` keys, `rule_id` strings, severities, and finding `message`
   texts are de-facto contract; keep byte-identical where feasible, extend only
   additively (`summary_json` is `dict[str, Any]` in `QualityReportRead`).
3. `QualityReportRead` / DB schema unchanged in stage 1 → **no Alembic
   migration required** for the modularization itself.
4. `QualityCheckCreate.profile` Literal stays `{"general", "tabular"}`; new
   profiles arrive in stage 2 with their own schema decision.
5. Upload/download/provenance/manifest code is out of scope and must not be
   touched by the migration (it already implements content-addressed storage,
   streaming upload hashing, path confinement — see `main.py:139-167,212-218`).

## 7. Reliability defects to fix within stage 1 (per instruction §四)

- **D1 measured hash**: record `measured_sha256`/`measured_size_bytes` in
  `summary_json` (additive) so every report names the exact bytes it examined.
- **D2 rule failure handling**: an unexpected exception inside the inline block
  today becomes an HTTP 500 with no report. The engine must isolate per-rule
  exceptions into `rule.execution_failed` **error** findings — a rule that
  crashes can never yield a passing report.
- **D3 versioning**: per-rule `version` attributes; report records the executed
  rule list with versions (additive in `summary_json.executed_rules`).
- **D4 duplicate detection memory**: `seen_rows` stores full row tuples
  (`main.py:278`) — O(total text) memory. Switch to per-row digests (bounded
  per row, still exact).
- **D5 migration test**: extend to `quality_reports` upgrade + downgrade.

## 8. What already exists and must NOT be reimplemented

Content-addressed artifact store with streaming upload hash + size cap + dedupe;
path-confined download with ETag/`X-Content-SHA256`; provenance with artifact
reference + checksum validation; lineage traversal; immutable DatasetVersion
manifests with canonical hashing; API-key gate; env settings; sync SDK. The
migration moves *only* the quality-check execution path.

## 9. Verdict

The service has a real, working quality floor (integrity + CSV structure +
content-addressed gating) and honest test discipline, but the engine is a
monolith inside one route handler: not composable, not independently testable,
not per-rule versioned, and silent about which bytes/rules produced a report.
Stage 1 extracts it into `tensordata/quality/` without API or schema changes,
closes D1-D5, and adds the missing reliability tests.
