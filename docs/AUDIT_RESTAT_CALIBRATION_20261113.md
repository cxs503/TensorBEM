**一句话**：11-11 交付的 `2,366` 不是「真实成果数」，而是「**有 PR 合并元数据**的 L2+ 单数」。
同一套方法在今天的群体上重算得 **3230**，两者之差既含群体增长也含记账字段补齐
——这恰恰说明该指标是元数据的函数，不是质量的函数。把它当质量指标，就会把
**元数据时代** 误读成 **产出质量**：pr_gate 键覆盖在 2026-10-26 周为 0.0%、
2026-11-09 周为 57.51%，
于是同类任务的口径凭空「变好」（§3.1、图2）。修正元数据与纯度两处缺陷后同口径 L2+ 为
**7352**（67.62%）；完整敏感性带见 §3.0。

## 2. 两处被量化的方法缺陷

### 缺陷 1：`pr_gate` 元数据的时代混杂
旧口径 strict 分支写的是 `merged = (pr_state=='merged')`，而 `pr_gate` 键**并非全程写入**：
全库 succeeded 中仅 4171 单（38.36%）带该键；带键者
96.72% 是 merged。也就是说键的存在与 merged 高度共线，
**缺失键几乎从不意味着「没合并」，而是「当时没记」**。旧口径把三者（merged / 未合并 /
未记录）压成二分，等于让任务创建日期决定成果档位。

### 缺陷 2：`*.py` 即「实现文件」的纯度污染
旧口径把任意代码扩展名文件计为实现。但工作树里大量根目录一次性脚本（`_scratch_*`、
`_patch_*`、`post_report_*`、`make_report_*`…）并不进入库内模块、无调用方，
按 L2 定义（独立功能实现）不成立。本审计把它们单列：**56** 单
（占被判「有实现」单的 0.75%）的实现文件**全部**是该类脚本。

### 缺陷归因（关键量）：差额几乎全是记账假象

旧口径 strict 与 loose 相差 **4281** 单。拆开看：

| 来源 | 单数 | 占差额 |
|---|---|---|
| `pr_gate` 键**缺失**（未记录，非未合并） | 4177 | 97.57% |
| 有键且明确**非 merged**（真未入库） | 104 | 2.43% |

即：把「严格 vs 宽松」读成「入库 vs 未入库」的质量差是错的——它 97.57%
来自记账字段的时代缺失。校准口径相对宽松口径共回落 159 单，归因互斥且清晰：
**56 单**「实现文件全部是随手脚本」（缺陷2）+ **103 单**
「有 pr_gate 键且明确非 merged」（真未入库，校准口径不动它）。

### 3.0 敏感性：不许用单点插补冒充事实

校准口径把「无 `pr_gate` 键」的任务按实测条件概率 q=96.72% 判为已入库，
这是最乐观端点。下表把 q 扫开，L2+ 期望值随假设连续变化：

| 假设 q = P(merged 给定无键) | 期望 L2+ | 被插补候选单数 |
|---|---|---|
| 0.0 | 3230.0 | 4150 |
| 0.25 | 4267.5 | 4150 |
| 0.5 | 5305.0 | 4150 |
| 0.75 | 6342.5 | 4150 |
| 0.967 | 7243.0 | 4150 |
| 1.0(max) | 7380 | 4150 |

读法：q=0 即旧严格口径（下界 3230）；q=1 即上界。真正的结论不是某个点，
而是**旧单点数字落在敏感性带的最低端**——它把 97.57%
的差额默认按 q=0 处理，而这个选择从未被论证。

## 6. 注意点与局限

1. 本审计只量化**分类器**的误差，不重新裁定任何单的 L 档，也不改任务/台账状态（owner 令：只重算账）。
2. `gate_level` 覆盖仅 236 单（2.17%），
   且审计抽样非随机（偏向有争议/新交付单），因此 §4 的一致率是**该子群**的一致率，
   外推到全库只能作为方向性证据，不能当全库精度。
3. 「一次性脚本」判据是文件名+路径启发式，会漏判把脚本放进 `scripts/` 的情形，
   故 56 是该污染源的**下界**。
4. 校准口径对缺失 pr_gate 键按 q=96.72% 判入库，是最乐观端点；
   §3.0 敏感性表把 q 从 0 扫到 1，故本文不要求读者接受任何单一插补假设——
   争议应落在「q 取多少」这个可讨论的点上，而不是「旧数字是不是真的」。
5. 分母选择（是否含「不可判」1097 单）会改变百分比，
   本文所有比例均以 succeeded 全量为分母，与原文一致以便对账。

## 7. 误差判定（是否 <3%）

本题无物理基准，故判据是**可复现性与内部一致性**，逐项给出：

| 检查 | 方法 | 结果 | <3%？ |
|---|---|---|---|
| 重统计可复现 | 从落盘 pinned CSV（10873 行）重算三口径聚合表与混淆矩阵，与实时库直算逐项比对 | all_match=True（表/L2+/混淆矩阵逐项） | 是（0 偏差） |
| 分档守恒 | 三口径各档计数之和 = succeeded 总数 | 三个口径均 = 10873 | 是（0 偏差） |
| 混淆矩阵守恒 | 每行计数之和 = 参与比较的 n | 已断言（见 tests/） | 是（0 偏差） |
| 抽样人工复核 | 固定种子(20261113)随机 5 单，回查 `changed_files` 前 8 项与分档理由，落盘 `spotcheck.md` | 5/5 档位理由与文件清单自洽（详见 artifact） | 是 |
| headline 误差棒（同群体同方法） | 严格 3230 vs 校准 7352（同一 10873 单） | 偏差 127.62% | **否**（远超 3%）——这正是本文结论：旧数字缺误差棒，不能按点值引用 |
| 跨快照可比性 | 旧交付 2366（群体 9117 succeeded）vs 本文同方法 3230（群体 10873） | 群体 +19.26%，数字 +36.52%，**非同快照不可相减** | **否**——引用必须带群体与快照时间 |

诚实声明：本文**否证**了 11-11 交付的方式（单点 headline + 18 对验证），
但**不否认**其结论方向（任务量 ≠ 成果量）。方向成立，量级需带区间。
