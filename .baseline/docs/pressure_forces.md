# Pressure and surface loads (`tensorbem.pressure`)

Status: verified post-processing layer, potential flow only. Introduced with
`tensorbem.benchmarks.sphere_flow` (uniform stream past a fixed sphere).

## 1. Why this module exists

Every other module of TensorBEM answers the question *"what is the velocity
potential?"*. Ship hydrodynamics asks the next question: *"what load does the
fluid put on the body?"*. Before this change the 3-D Laplace part of the
library had no pressure or force post-processing at all: added mass was
obtained from the boundary energy integral, and there was no way to turn a
solved potential into a pressure field, a resultant force, or a moment. The
README explicitly flagged this gap ("off-body velocity for force integration
must be evaluated clear of that layer") without providing the integrator.

`tensorbem.pressure` closes it with a deliberately small, exactly verifiable
surface integral:

| function | purpose |
|---|---|
| `steady_pressure_coefficient(velocity, U)` | `Cp = 1 - |v|^2 / U^2` for a steady potential flow |
| `bernoulli_pressure(velocity, ...)` | `p = p_inf + (1/2) rho (U^2 - |v|^2) - rho dphi/dt` (steady/unsteady) |
| `hydrostatic_pressure(points, ...)` | linear field `p = rho g (z_fs - z)` |
| `integrate_pressure_loads(mesh, pressure, ...)` | `F = int p n dS`, `M = int (x-c) x p n dS` |
| `steady_pressure_loads(mesh, velocity, U, ...)` | the Bernoulli -> `Cp` -> loads chain in one call |

## 2. Formulation and conventions

Unsteady Bernoulli for an incompressible, irrotational flow in an inertial
frame is `dphi/dt + |v|^2/2 + p/rho = C(t)`. Taking the free stream as the
reference (`|v| -> U`, `dphi/dt -> 0`) gives

```
p - p_inf = (1/2) rho (U^2 - |v|^2) - rho dphi/dt ,
```

which is what `bernoulli_pressure` evaluates. The free-stream *direction* never
enters: it is already contained in the total velocity `v = U + grad(phi_d)`.
For a body in a fluid at rest (`U = 0`) the same expression reduces to
`p = p_inf - rho dphi/dt - (1/2) rho |v|^2`.

Sign conventions (asserted in the tests, not just documented):

* `TriangleMesh` normals point **out of the body into the fluid**.
* `PressureLoads.force = int p n dS`; the load **on the body** is
  `PressureLoads.force_on_body = -int p n dS`.
* `PressureLoads.moment = int (x - c) x p n dS` about `reference_center = c`;
  `moment_on_body` is its negative.
* A uniform `reference_pressure` is removed before integration (a closed body
  cannot feel it) and recorded in the result.

Quadrature is exact, not approximate, for the fields that matter here:
`int_T p dS = area * p` for constant `p` on a flat triangle, and the centroid
rule is still exact for a **linear** `p` because the centroid is the
area-weighted mean of a linear function over a triangle while the panel normal
is constant. Hence a hydrostatic field reproduces Archimedes to round-off on
any closed faceted mesh, at any resolution.

## 3. Verification

Three independent classes of reference are used. None is generated by the code
under test.

### 3.1 Exact identities of the integrator

| case | analytic reference | measured |
|---|---|---|
| uniform pressure on a closed mesh (icosphere, ellipsoid) | `F = 0`, `M = 0` | `|F| / (p A) < 2e-16`, `M = 0` |
| linear field `p = c . x`, `c = (3, -2, 5)` | `F = c V` (divergence theorem) | `rtol < 1e-13` (test `test_linear_pressure_matches_divergence_theorem`) |
| hydrostatic `p = rho g (z_fs - z)` | `F_body = -rho g V z_hat`, `M = 0` about the centre | `rel < 2e-16` |
| reference-point shift | `M(c) = M(0) - c x F` | `atol < 1e-12` |

The volume `V` in these references is the signed volume of the closed mesh,
computed by the independent tetrahedron sum in `TriangleMesh.volume`; the
hydrostatic identity therefore cross-checks the force integrator against the
geometry kernel.

### 3.2 Classical closed form: uniform stream past a sphere

For a sphere of radius `a` at the origin in a uniform stream `U` along `+x`
(Lamb 1932, §103), `phi_d = U a^3 cos(theta)/(2 r^2)`, the total surface speed is
`(3/2) U sin(theta)`, and

```
Cp(theta) = 1 - (9/4) sin^2(theta),   Cp(stagnation) = 1,   Cp(equator) = -5/4,
```

with a **zero** pressure resultant (d'Alembert's paradox). The numerical chain
is: exterior Neumann BVP with the closed-form fluid-normal derivative
`q_e = U cos(theta)` -> second-kind solve `(1/2 I - H) u = S q_e` -> recovered
surface velocity `grad_tan(u) + n dphi/dn` -> Bernoulli -> per-panel `Cp` ->
pressure integral.

| subdivisions | panels | h_mean | Cp rel. L2 | Cp max abs | |C_F| (-) | Archimedes rel. | kappa(1/2 I - H) | observed order |
|---|---|---|---|---|---|---|---|---|
| 0 | 20 | 1.0515 | 2.955e-01 | 3.386e-01 | 5.14e-09 | 0.0e+00 | 2.34 | -- |
| 1 | 80 | 0.5823 | 8.021e-02 | 1.098e-01 | 2.95e-09 | 0.0e+00 | 2.17 | 2.21 |
| 2 | 320 | 0.2993 | 2.663e-02 | 5.664e-02 | 3.60e-10 | 1.8e-16 | 2.08 | 1.66 |
| 3 | 1280 | 0.1507 | 1.086e-02 | 2.616e-02 | 1.40e-11 | 1.7e-16 | 2.04 | 1.31 |

`kappa(1/2 I - H)` stays `O(1)` under refinement while the single-layer operator
`kappa(S)` is `37.57` at 320 panels: this is the numerical reason the
second-kind formulation is used for the surface solve, and it is the
conditioning diagnostic recorded for this case.

### 3.3 What the zero-resultant check does *not* prove

The integrated force coefficient is `~1e-10` for the numerical `Cp` field and
`~1e-16` when the **analytic** `Cp` is integrated over the same faceted mesh.
The small numerical residual is mostly *closed-surface cancellation on a nearly
symmetric mesh*, not evidence that `Cp` is accurate: the field-level error is
`2.7e-2` at the same mesh level. The two numbers are reported separately in the
benchmark so the distinction is visible; the `Cp` assertions, not the force
assertion, are what bound the accuracy of the solution.

## 4. Error judgement

Against the platform criterion "relative error > 15% is unacceptable, < 3% is
the target" for a quantity compared with a reference:

* **`Cp` field, 320 panels (the default verification level): relative L2 error
  2.66e-2, i.e. 2.7% -> within the 3% target.**
* `Cp` field, 1280 panels (finest level run): 1.086e-2, i.e. 1.09% -> within
  the 3% target with a factor 2.7 of margin.
* `Cp` field, 80 panels: 8.0e-2 (8.0%) -> usable, not at target.
* Extreme values: `Cp` at the stagnation points within 0.065 of 1, `Cp` on the
  equator within 0.022 of -5/4 (absolute `Cp` error `<= 5.7e-2` for a range of
  2.25).
* Pressure resultant: `|C_F| = 3.60e-10` at 320 panels and `1.40e-11` at 1280
  panels against the exact value 0 (dimensionless, normalised by
  `0.5 rho U^2 pi a^2`).
* Integrator identities: at round-off (`<= 2e-16`).

The observed order of the `Cp` error drifts from `2.21` (20->80 panels) to
`1.66` (80->320) and `1.31` (320->1280); the mesh sequence is therefore still
pre-asymptotic in this measure at the finest level available, and the `1.31`
value should not be read as the asymptotic order of the method. The boundary
potential itself converges at second order (see `docs/three_dimensional_bem.md`);
`Cp = 1 - |v|^2/U^2` squares the recovered velocity, so it inherits a doubled
relative error of the tangential-gradient recovery rather than the order of the
potential.

## 5. Limitations and pitfalls

1. **Only the potential-flow pressure is modelled.** No viscous (friction)
   pressure, no free-surface elevation coupling, no forward-speed Munk moment,
   no flow separation. In particular, the zero drag reported here is
   d'Alembert's paradox, not a prediction of ship resistance.
2. **The linear hydrostatic field is not clipped at the waterline.** Points
   above `z_fs` return negative gauge pressure. For a partially submerged body
   restrict the integral to the wetted panels (as
   `WettedHullMesh.wetted_faces` does) before calling the integrator.
3. **`Cp` from the recovered surface velocity inherits its `O(h^1.5-2)` error.**
   The representation-based surface velocity
   (`evaluate_representation_surface_velocity_at_panels`) must not be used for
   pressure: it carries `O(1)` error (see `docs/three_dimensional_bem.md`).
4. **Faceted geometry.** The sphere benchmark prescribes the exact sphere data
   at the panel-centroid angular position, which is the standard constant-panel
   choice in this repository; the diagnostic
   `normal_velocity_residual ~ 1.9e-2` at 320 panels quantifies how far the
   faceted panel normal departs from the radial direction, not a solver error.
   Prescribing the flux through the panel normal instead changes the `Cp` error
   only from `2.66e-2` to `2.74e-2`, so the discretisation, not the data
   placement, dominates.
5. **Dense direct solve.** The 3-D surface systems are dense and intended for
   verification meshes; the pressure integrator itself is `O(F)` and can be
   used with any panel set.

## 6. Reproduction

```bash
# single level
python -m tensorbem.benchmarks.sphere_flow --subdivisions 2
# refinement study + figure + machine-readable artifact
python -m tensorbem.benchmarks.sphere_flow --levels 0 1 2 \
    --output docs/sphere_flow_study.json \
    --markdown docs/sphere_flow_study.md \
    --plot docs/figures/sphere-flow-cp.png
pytest tests/test_pressure.py tests/test_sphere_flow_benchmark.py -q
```

The committed artifact `docs/sphere_flow_study.json` and the table above are
produced by exactly these commands; the table is regenerated with
`--markdown` so no number is transcribed by hand.
